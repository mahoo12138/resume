# Resume

这个项目使用 Nuxt 渲染静态简历页面，简历内容直接来自根目录的 `RESUME.md`。

## 内容来源

- 顶部 frontmatter 用来维护基础信息。
- 正文使用 `##` 作为一级 section，解析器会按 section 标题匹配对应规则。

## Markdown 规则

### Frontmatter

支持的常用字段：

```yaml
---
name: 黄昌河
nickname: Mahoo12138
job: 前端开发工程师
experience: 约 4 年开发经验
specialty: 企业级 SaaS / 物联网平台
location: 上海 / 广州 / 深圳
phone: 15xxxxxxx14
email: example@example.com
blog: https://example.com
github: Mahoo12138
updated: 2025-04-12
---
```

- `updated` 为可选字段，建议使用 `YYYY-MM-DD` 或 ISO 日期格式。
- 如果未提供 `updated`，页面不会显示“最后更新时间”。
- `experience`、`specialty` 为可选的职业年限和专业方向，显示在页头；未填写时隐藏，不根据毕业时间自动推算工龄。
- 页头将学历、学校、专业合并显示；原有性别、出生年月与毕业年份字段仍可解析，但不在页头展示。

### 行内标记

正文与列表项内的行内标记跟随当前主题渲染，可用于任意 section：

- `**文字**`：加粗，用于条目开头的能力名，例如 `- **通用地图框架** — ...`。
- `++文字++`：下划线，用于需要被一眼扫到的成果，例如 `++交付 7,600 余行代码++`。
- `` `文字` ``：等宽底纹，用于接口名、配置项等标识符。

约束：

- `++` 必须成对且不跨行，未配对的按普通文本渲染；标记可以嵌套，如 `++**重点**++`。
- 反引号内的 `++` 不参与解析。
- 正文不解析原始 HTML，`<u>文字</u>` 会原样显示，下划线请用 `++文字++`。

### 注释

`<!-- 注释 -->` 不会出现在页面上，可以写在正文中间，也可以整块包住暂时不想展示的内容：

```md
交付 ++7,600 余行代码++<!-- 内部备注，不对外 -->。

<!-- ### 暂停展示的项目

+ 仓库: https://example.com/draft

整段都不会渲染。 -->
```

约束：

- 注释在结构化解析之前剥离，被注释掉的 `###` 标题不会成为条目。
- 只剥离首尾配对的注释；未闭合的 `<!--` 连同其后内容按普通文本显示，避免整段简历被静默隐藏。
- ` ``` ` 围栏代码块内的 `<!--` 属于示例内容，不剥离。
- 注释行剥离后会留下空行，与手写空行等效。

### 元信息行

紧跟在分组 / 条目开头的 `+` 行解析为元信息，按「链接之外」的第一个冒号切成 `键: 值`，页面只显示值：

- `+ 任职时间: 2022.07 ~ 2026.03` → 显示 `2022.07 ~ 2026.03`。
- `+ [Numen](https://github.com/x/numen)：说明` → 冒号前已有链接，整行按富文本渲染，链接名和说明都保留。
- URL 里的 `https:` 不算分隔符，因此 `+ 仓库: [x](https://…)` 与 `+ [x](https://…)：说明` 两种写法都能正确渲染。

### 已内置的 section 规则

#### `## 个人技能`

按富文本解析，直接把整段 Markdown 渲染成 HTML。

```md
## 个人技能

- 熟练掌握 Vue / React / TypeScript
- 熟悉工程化、性能优化和组件设计
```

#### `## 工作经验`

按“分组 + 条目”解析：

- `###` 表示公司 / 团队 / 任职单位
- 紧跟在分组开头的 `+` 行会被解析为分组元信息
- `####` 表示该公司下的业务系统
- 紧跟在条目开头的 `+` 行会被解析为条目元信息
- `#####` 表示系统下的各端工程（如司机端、PC 管理端），其后的正文或列表描述该端职责

```md
## 工作经验

### 汉得信息

+ 2022.07 ~ 至今

#### 马达物流云

+ 协作开发

物流供应链业务系统，包含管理端及司机端。

##### PC 管理端

- 负责物流跟踪、页面配置和流程引擎模块开发。

##### 司机端

- 负责移动端业务页面开发。
```

#### `## 项目经历` / `## 开源作品`

按“条目列表”解析：

- `###` 表示单个项目 / 作品标题
- 紧跟在条目开头的 `+` 行会被解析为元信息
- 后续正文按 Markdown 渲染

```md
## 开源作品

### resume-parser

+ Nuxt / TypeScript
+ 独立开发

一个将结构化 Markdown 简历转换为页面数据的解析器。
```

### 自定义 section

- 未在解析器内置规则中的 `##` section，会默认按富文本处理。
- 如果你后面要新增一种结构化 section，只需要在解析器规则表里增加一条规则即可。

## 打印与投递

点击“打印”后可选择公开脱敏版，无需输入完整手机号。本人生成投递版时，在同一弹窗输入完整手机号后选择“打印投递版”。手机号仅保留在本次页面的临时状态中，不上传、不写入浏览器存储；打印窗口关闭后通过 `afterprint` 清理，关闭弹窗和再次打开弹窗时也会清理。公开打印会忽略输入框内容，防止上一次投递版的号码被带入。

不要把真实手机号写入公开的 `RESUME.md`。项目仓库链接使用可识别的地址文本，以便打印阅读；打印页脚指向实际简历站点。

## 测试

测试使用 Node.js 22.14.0 的内置 test runner 与类型擦除功能，通过 `pnpm test` 运行，不增加依赖。覆盖手机号输入边界、Markdown 元信息和多级经历解析。构建使用 `pnpm build`；浏览器中还需检查公开打印、投递版校验、取消与重复打印、移动端及 A4 分页。

## 开发命令

安装依赖：

```bash
pnpm install
```

启动开发环境：

```bash
pnpm dev
```

构建生产版本：

```bash
pnpm build
```

预览生产构建：

```bash
pnpm preview
```
